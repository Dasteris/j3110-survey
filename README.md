# Опрос группы J3110

Статический сайт (без сборки) — еженедельная анкета с карточками по предметам +
дашборд старосты. Данные в Firebase (Firestore + Authentication).

**Сайт:** https://dasteris.github.io/j3110-survey/ · **Дашборд:** `/admin.html`

## Как это устроено

- **Вход:** ИСУ + личный код. У каждого студента аккаунт в Firebase Auth
  (uid = ИСУ, пароль = код), у старосты дополнительно claim `admin`.
- **Доступ проверяет сервер** (`firestore.rules`), а не браузер:
  - студент читает и пишет только свой ответ и только про открытую для опроса неделю;
  - все ответы и список группы читает только староста.
- **Неделя опроса** — всегда прошедшая (пн–вс по Москве), ответы принимаются
  всю следующую неделю. Пример: с 21.09 по 27.09 открыта анкета про 14.09–20.09.
  Ответы хранятся под датой понедельника оцениваемой недели
  (`getSurveyWeekId` в `common.js`); правила считают то же по серверному времени.
  В понедельник 00:00 МСК открывается анкета про только что закончившуюся неделю.
- `subjects.js` — предметы, преподаватели и поля карточек. Названия частично
  восстановлены по обрезанному скриншоту расписания — стоит перепроверить.

## Локальные файлы (не в git)

- `roster.local.js` — список группы: ФИО, ИСУ, телеграм, кто староста.
- `codes.local.json` — коды входа `{ "ИСУ": "код" }`.
- Ключ сервисного аккаунта Firebase — держите вне папки проекта.

## Настройка / изменения группы

```bash
npm install
node scripts/setup-firebase.js /путь/до/serviceAccount.json
```

Скрипт можно запускать повторно:

- включает вход по email/паролю, пишет `firebase-config.js`;
- загружает ростер в Firestore, заводит недостающие аккаунты и выдаёт им коды;
- деплоит `firestore.rules`.

Существующие коды он не меняет. Перевыпустить код (старые сессии этого человека
разлогинятся):

```bash
node scripts/setup-firebase.js /путь/до/key.json --reset 558392
node scripts/setup-firebase.js /путь/до/key.json --reset-all
```

Для нового Firebase-проекта сначала один раз вручную в консоли: создать
Firestore Database и нажать **Get started** в Authentication — на это у
сервисного аккаунта нет прав.

## Рассылка в Telegram

`scripts/send-reminders.js` пишет каждому с **вашего** аккаунта: просьбу пройти
анкету, ссылку, ИСУ и код. Пропускает старосту и тех, кто уже ответил на этой
неделе. Между сообщениями пауза 15–30 с. Бот здесь не подходит: он не может
написать человеку по @нику первым.

1. Возьмите `api_id` и `api_hash` на https://my.telegram.org → API development tools.
2. Войдите один раз (сессия сохранится в `telegram.local.json` — это полный
   доступ к вашему Telegram, никому не отдавайте):
   ```bash
   node scripts/send-reminders.js login
   ```
3. Проверка без отправки — кому уйдёт и пример текста:
   ```bash
   node scripts/send-reminders.js --key /путь/до/serviceAccount.json
   ```
4. Отправить сейчас: добавьте `--send`.
5. Каждую неделю (по умолчанию понедельник 10:00, после сброса анкеты) через launchd. Ключ должен лежать
   не в Downloads/Documents/Desktop — фоновые задания macOS туда не пускают:
   ```bash
   scripts/install-weekly-reminders.sh ~/.config/j3110-survey/serviceAccount.json
   ```
   Mac в это время должен быть включён (сон — ок, запустится при пробуждении).
   Лог: `reminders.local.log`.
